# 图像多级分类：从层级约束到 VLM 与 Taxonomy 的协同

> 面向大规模、多品类、层级化标签体系的图像分类，是工业界商品/素材/内容图片治理的核心任务之一。本文从任务定义出发，梳理近几年层级图像分类的代表性工作，并结合本人技术实践中的借鉴思路与经验教训，探讨"视觉语言模型（VLM）+ 品类树（Taxonomy）+ 约束解码"这条更贴近落地的路线。

---

## 1. 任务定义：我们到底在解决什么问题

在讨论方法之前，需要先澄清一个常被混淆的概念。图像"多级分类"实际上对应着两条不同的任务线：

- **层级单标签分类（hierarchical single-label classification）**：一张图片对应**一条**完整的类别路径，例如「服饰 → 女装 → 外套 → 羽绒服」。这里的"多品类"指的是**整个数据集包含大量品类**，而非单张图片包含多个分类项。
- **层级多标签分类（hierarchical multi-label classification）**：一张图片同时拥有**多个**类别路径或标签集合，常见于医学影像（"胸部 → 肺部 → 肺炎"）和遥感场景。

对于商品、素材、内容图片的治理场景，绝大多数情况下属于**前者**：每张图通常只应输出一个叶子品类及其祖先路径。这一定位至关重要，因为它直接决定了技术选型——医学影像和遥感中的多标签方法只能作为**层级约束的参考**，而不应作为主线。

形式化地，设品类体系为一棵树（或更一般的有向无环图），图片 $x$ 的真实叶子类别为 $y_L$，对应路径为：

$$
y_1 \rightarrow y_2 \rightarrow \cdots \rightarrow y_L
$$

模型需要预测完整路径 $\hat{y}_1, \hat{y}_2, \ldots, \hat{y}_L$。一个合格的预测至少要满足两个条件：

1. **分类准确**：叶子类别尽可能正确；
2. **层级一致**：不能预测出"植物 → 蜂鸟"这种父子关系冲突的路径。

---

## 2. 核心难点

与普通 flat 多分类相比，层级分类面临一组独特的困难：

- **不同层级依赖不同的视觉线索**：粗粒度依赖整体形状，细粒度依赖局部纹理、颜色和部件；
- **类别不平衡与长尾**：大类样本充足，尾部细分类别样本稀少；
- **层级约束**：子类为真时，所有祖先类通常也必须为真；
- **层级深度与粒度不稳定**：不同品类的层级数可能不同，有的两级、有的四五级；
- **层级标注成本高**：业务数据往往只有叶子标签，需要补全父类或自动构建 taxonomy；
- **粗分类错误会向下传播**：一旦粗粒度选错，细粒度再准也无济于事。

这些难点共同决定了：**只做一个固定叶子类别的 softmax 分类器，在真实业务中往往难以泛化**。这也是本文后续讨论的出发点。

---

## 3. 代表性方法梳理

近几年层级图像分类的研究大致形成了四条相互交织的路线，下面逐一说明，并注明对应的论文。

### 3.1 显式多级输出：为每个层级单独建分类头

最直观的做法是共享一个图像 backbone，然后为不同层级建立不同的分类头，各层交叉熵加权训练。较早的代表工作是 **ML-CapsNet**（A Capsule Network for Hierarchical Multi-Label Image Classification）[1]，它为每个层级设置独立的 secondary capsule 分支，并联合优化各层分类损失与图像重构损失，在 CIFAR-10/100 上报告了粗、中、细三级各自的准确率。其核心价值在于：**不是先预测叶子再"反推"父类，而是让所有层级共同参与训练**，层级结构约束有助于提高预测一致性和收敛速度。

但这类结构有一个明显缺陷：各层分类头可能关注图片中的**不同区域**，导致粗类别和细类别互相矛盾（例如粗分类头看到"自行车"、细分类头看到"帽子"）。因此它适合作为工程 baseline，但不足以单独解决层级一致性问题。

### 3.2 概率约束：显式保证父子节点一致

**TLMCM**（TLMCM Network for Medical Image Hierarchical Multi-Label Classification）[2] 采用了更直接的层级约束方式。对于父节点 $A$，其概率由所有后代节点中的最大概率决定：

$$
\mathrm{MCM}_A = \max_{B \in D_A} h_B
$$

其中 $D_A$ 表示节点 $A$ 的后代集合。这样，如果某个子节点概率很高，父节点就不会出现极低概率，从而从机制上降低层级冲突。论文还设计了 Maximum Constraint Loss 将其纳入反向传播。

尽管 TLMCM 面向医学 X-ray 影像，但它给出的启发对商品场景同样适用：**当标签体系是树结构、需要严格避免父子冲突、且希望输出完整路径时，"子概率向父传播"的约束是低成本且有效的**。需要注意的是，$\max$ 操作可能使梯度只集中在最高概率子节点上，在存在多父节点或多个合理子类别时不够灵活。

### 3.3 图结构 + 视觉语言模型：让 taxonomy 参与表示学习

**HGCLIP**（HGCLIP: Exploring Vision-Language Models with Graph Representations for Hierarchical Understanding）[3] 代表了近几年一个重要转向：不再把 taxonomy 仅仅当作后处理规则，而是**直接将其编码成图**参与学习。其流程大致为：

1. 用 CLIP 的文本编码器获得类别名称表示；
2. 将父子类别构造成图，用图神经网络进行消息传递；
3. 对图像特征学习类别视觉原型，并让原型也在层级图上传播；
4. 通过注意力机制将层级类别信息注入图像区域特征。

这条路线特别适合**类别名称语义丰富、需要零样本/少样本迁移、品类频繁新增**的商品或开放类别场景。HGCLIP 在 11 个层级视觉识别 benchmark 上评估，其价值在于让"羽绒服属于外套、外套属于女装"这类知识直接进入模型表示，而非仅仅停留在 prompt 或后处理里。

### 3.4 视觉一致性：让不同层级关注同一个物体

**H-CAST**（Visually Consistent Hierarchical Image Classification）[4] 提出了一个很关键的观察：层级分类错误不只是"标签关系没有建模"，还可能是**不同层级的分类器在看图片中的不同区域**。它通过从细到粗的视觉分组，使细粒度和粗粒度分类器关注同一物体的不同尺度区域，并配合 Tree-path KL 损失约束整条树路径的一致性：

$$
\mathcal{L} = \mathcal{L}_{\mathrm{HV}} + \alpha \mathcal{L}_{\mathrm{TK}}
$$

在 BREEDS 数据集上，H-CAST 的 Full-Path Accuracy 相较最强对比方法 HRN 有 4.25～6.36 个百分点的提升。它的启发在于：**如果图片中经常包含背景、多个物体或局部细节，不能只做"多分类头 + 分类损失"，还需要考虑不同层级是否对同一目标形成了视觉 grounding**。

### 3.5 零样本与层级 prompt：不训练也能用

**CHiLS**（CHiLS: Zero-Shot Image Classification with Hierarchical Label Sets）[5] 是零样本层级分类的典型代表。它不是只给 CLIP 一个粗粒度类别名，而是为每个父类构造若干子类，在更细的子类空间做图文匹配，再把子类预测映射回父类。

CHiLS 论文中一个非常有价值的结论是：**当有真实层级结构时，其在多个 benchmark 上相较普通 superclass 零样本分类有明显提升；但如果层级是由 GPT-3 自动生成的，收益则大幅缩小**。这直接印证了一个工程判断：**LLM 可以辅助生成 taxonomy，但不能替代真实、准确的业务类目树**。

### 3.6 VLM/LMM + taxonomy 约束解码

对于商品类目这种大规模、业务特有的场景，近年来的方向是：让多模态大模型负责提取和理解图像语义，但**最终类别选择交给 taxonomy-aware classifier 或约束解码器**，而不是让 LMM 自由生成任意文本。

**TTC**（Leveraging Taxonomy and LLMs for Improved Multimodal Hierarchical Classification）[6] 是这条路线在电商场景的代表。它在 MEP-3M 电商商品数据（超过 300 万条多模态商品数据）上实验，提出 Taxonomy-based Transitional Classifier：在多模态 backbone 后面增加一个 taxonomy-aware 输出层，用**父子转移矩阵**约束下一层的候选：

$$
m^{(\ell_{i+1})} = \hat{y}^{(\ell_i)} M^{[\ell_i,\ell_{i+1}]}
$$

即上一层的预测概率通过父子关系矩阵调节下一层分类器的输出，使其更倾向于选择当前父类别下的子类别。论文报告，加上 TTC 后，各多模态 backbone 的层级准确率与一致性均有显著提升。

这条路线给出的启发很清晰：**VLM/LMM 可以负责"看懂"，但"选对合法路径"最好由受 taxonomy 约束的层来完成**。否则让 LMM 直接输出"服饰→女装→外套→羽绒服"，容易出现输出不存在的类目、类目名称变体、父子关系错误、同义词对不上等问题。

### 3.7 检索增强：不依赖 VLM 记忆业务类目

商品场景中单纯 prompt 往往不够，因为存在大量业务特有概念（如某平台内部定义的"轻奢女包"、"白底图"等），这些未必出现在预训练 VLM 的自然语言分布中。因此实际系统常采用**检索增强**：构建类别原型库、每个类目的代表图片、类目标题与属性文本、同级类别的 hard negative，用图像/文本 embedding 召回 top-k 候选，再由 VLM 在候选内做终选或跨模态重排。此时 VLM 主要负责"召回和匹配"，而非单独承担最终决策。

### 3.8 taxonomy 表示对齐：更前沿的方向

**TARA**（Taxonomy-Aware Representation Alignment for Hierarchical Visual Recognition with Large Multimodal Models）[7] 代表了 2026 年的更新路线：不是只在输入端写 prompt，而是**直接训练 LMM 的内部表示，使其具有 taxonomy-aware 结构**——用层级知识丰富的视觉基础模型作为 teacher 对齐 LMM 的中间表示，推理时不再依赖 teacher。虽然目前主要在生物分类上验证，但其"用 taxonomy 对齐表示而非堆 prompt"的思想可迁移到商品 taxonomy。

### 3.9 文字密集图像的特殊挑战

商品和广告图场景有一个独特风险：**图像里的文字既可能是最有价值的品类证据，也可能是最强的噪声来源**。已有研究将嵌入图像中的误导性文字会改变视觉语言模型预测的现象称为 **typographic attack / typographic bias**。

**TAP-VL**（arXiv:2411.04642）[8] 专门讨论了 OCR 的建模方式：直接把 OCR token 前置到 LLM 输入会**丢失二维布局**，并在文字密集图像中带来高计算开销。它把 OCR 视为一个**带二维位置的独立模态**，用固定数量的 query token 压缩长 OCR 序列。

这提示我们：广告图不能简单做"图像 + OCR 文本拼接"，而应把视觉主体、图片内文字、版式位置、外部商品文本拆成**独立信号**再做门控融合；更不能简单"去文字训练"——相关文本可以增强图文对齐，**误导文本才是问题**。

## 4. 方法选择的一张"连续谱"

综合以上工作，可以看清一个关键事实：当前主流**并不是**在"训练分类器"和"纯提示词工程"之间二选一，而是形成了一个连续谱：

> **预训练视觉语言模型负责开放语义泛化，taxonomy 负责约束候选空间和输出路径，少量训练/参数高效适配负责补足领域视觉差异。**

其中各环节的分工大致如下：

| 环节 | 解决的问题 |
| --- | --- |
| prompt engineering | 类别语义表达 |
| VLM embedding | 开放类别泛化 |
| taxonomy graph / transition matrix | 父子关系合法性 |
| 检索增强 | 业务特有类目与长尾类 |
| adapter / prompt tuning | 领域视觉差异 |
| 路径解码 | 输出合法性 |
| 少量标注训练 | 商品图与通用互联网图像的分布差异 |

固定叶子 softmax 之所以"很难泛化"，根本原因在于：新类需要扩展输出维度、类别名称语义未被利用、taxonomy 改变后需要重构模型。而"开放词汇 VLM + taxonomy 图 + 类别原型检索 + 层级路径重排 + 参数高效适配"的组合，则让新类别只需要：编码新类别名称、接入 taxonomy、必要时少量样本更新 adapter，而不必重训整个分类器。

## 5. 本人实践：思路借鉴与经验总结

在一段面向商品图片的多级品类分类实践中，我沿着上述综述的思路做了取舍和落地。以下是可复用的经验，用"本人实践"代指，不涉及具体代码与数据。

### 5.1 候选空间管理与分阶段分类

面对上千条叶子路径的品类树，**一次性把所有叶子塞进 prompt 是不可行的**——既超出上下文，也引入大量硬负样本。我的做法是**分阶段（staged）分类**：从根开始，每阶段只展示当前子树内的一组候选路径，让模型选一个前缀，再据此裁剪子树、进入下一阶段，直到落到叶子。

这与 TTC [6] 的"父子转移矩阵约束候选"思路同源，但更轻量——不训练分类头，而是用**候选预算**控制每阶段枚举的候选数量。经验是：**粗粒度层（L1/L2）候选少、几乎不需要预算约束；细粒度层候选多，是 prompt 最大的阶段**，也是收益最明显的优化点。

### 5.2 模型输出不作为最终真相，taxonomy 负责兜底

一个反复验证的教训是：**模型的自由文本输出不可信**，可能出现不存在的类目、类目名称变体、父子关系错误、同义词对不上等问题。因此我采用了与 [6] 相同的原则——**模型只负责"选路径"，系统负责路径合法性、canonical 标签和编码回填**。

具体做法是让模型在**受限的候选集合**中做选择（例如用 JSON Schema 的 enum 约束），选出的路径再经过 taxonomy 的权威校验，命中才返回 canonical 路径与编码。这样即使模型"想越界"，也会被约束机制拦在合法空间内。

### 5.3 结构化输出的可靠性差异

在让模型输出结构化结果时，我观察到**强 schema 约束（如 json_schema）比"普通 JSON object"的提示更可靠**；同时，**用候选路径的扁平列表比缩进树更不容易产生层级歧义**。另一个细节是：解析模型输出时，应**优先从结论语境中提取候选路径**，而不是从候选列表尾部误提取——这在细粒度、候选名相近时尤其重要。

### 5.4 闭集与开放集要显式分离

实践中的一个关键决策是**把"闭集 benchmark"和"全量开放品类树"两种模式显式分开**，且**不要在全量模式下沿用闭集的语义纠偏逻辑**。闭集小规模场景可以靠规则修正提升精度，但这类纠偏一旦泛化到大规模品类树，反而会成为噪声来源。经验是：闭集和开放集的行为差异应保持"物理隔离"，避免一套后处理逻辑同时服务两种目标。

### 5.5 广告文字的"有条件可信"策略

对于广告/素材图，文字既是强证据也是强噪声。我借鉴了 [8] 的思路，明确了一个原则：**不要简单全量 OCR 拼 prompt，也不要去文字训练**，而是把文字当作"有条件可信的证据"：

- 品类词（如"羽绒服"）高权重；
- 品牌/型号词中高权重；
- 促销词（"限时五折"）在品类分类中低权重；
- 水印、平台词、免责声明通常屏蔽。

关键洞察是：**真正的问题不是"模型不认识这句话"，而是"模型不知道这句话在当前图片中扮演什么角色"**。在没有完整多模态门控融合能力时，一个轻量折中是让模型在粗分类阶段同时输出对图片主体的一句话语义描述，用于后续阶段的候选召回，从而把"看图"和"看字"的职责拆开。

### 5.6 检索候选优于单纯扩大 prompt

当品类树继续膨胀时，仅靠结构预算裁剪会退化——候选列表里混入大量无关的硬负样本。我评估后发现，**层级 RAG（逐级检索召回候选）+ schema enum 约束**是比"flat 向量检索"和"纯扩大 prompt"都更稳的路线：每级候选少、召回率高，且与分阶段流程天然兼容。核心前提是**每级检索召回率要足够高**（否则检索误差会吃掉收益），因此在接入管线前，先做离线召回评估是必要的门槛。

## 6. 评测指标：不要只看叶子 Top-1

只报告叶子节点 Top-1 Accuracy 会掩盖"错得很远"和"错到相邻子类"之间的巨大差异。实践中我建议至少同时报告：

| 指标 | 作用 |
| --- | --- |
| 各层准确率（L1/L2/L3…） | 逐级定位错误来源 |
| Full-Path Accuracy（FPA） | 整条路径全对才算对，同时衡量准确性与层级一致性 |
| 层级距离误差 | 预测错误距离真实类别在 taxonomy 中的树距离 |
| Macro-F1 / per-class recall | 应对长尾类别 |
| Top-k 路径准确率 | 前 k 条候选路径是否覆盖正确路径 |
| taxonomy 合法率 | 输出路径是否落在合法 taxonomy 内 |

其中最重要的主指标是 **FPA**，H-CAST 也将其作为同时衡量准确性和层级一致性的指标 [4]。对业务而言，还可以补充一个"可接受错误"的度量：预测到同一二级类目下的相邻叶子算轻微错误，预测到完全不同一级类目算严重错误——这比普通 accuracy 更符合业务实际。

## 7. 结语

图像多级分类（层级单标签分类）的核心，不是"识别图片里有多少个类别"，而是**在一个很大的类别体系中，为每张图片找到一条合法、准确、可解释的分类路径**。

综合近几年的工作与本人实践，可以提炼出这样一条务实的主线：

> **固定分类头很难泛化，但"VLM + taxonomy + 少量领域适配 + 约束解码"是更主流、更稳定的方向。** 其中，prompt 解决语义表达，VLM embedding 解决开放类别泛化，taxonomy 图/转移矩阵解决父子关系，检索增强解决业务类目与长尾，路径解码解决输出合法性，少量标注训练解决分布差异。

对于工程落地，最值得优先借鉴的是：用 **TTC [6] 式的 taxonomy 约束解码**保证路径合法性、用 **H-CAST [4] 的视觉一致性思路**处理复杂背景与细粒度差异、用 **HGCLIP [3] 的标签图建模**利用类别语义、并在文字密集场景遵循 **TAP-VL [8] 的"OCR 作为独立模态"**原则。而这一切的前提，是拥有一棵**真实、准确的业务 taxonomy**——LLM 只能辅助构建，不能替代。
